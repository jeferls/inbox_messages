Postback Gateway

Dispara um postback via POST {base}/gateway/webhook, simulando o retorno de status de um gateway de pagamento (Cielo, Pagarme, Worldpay, etc.) para o greenn-back. É necessário que já exista uma venda (Sale) no banco com o transaction_id informado.
Atenção: este postback atualiza o status real da venda vinculada ao transaction_id. Use com cuidado, principalmente em Staging.
Ambiente
O caminho /gateway/webhook é adicionado automaticamente.
Importa o transaction_id da venda escolhida.
Enviado como id — usado para localizar a venda pelo transaction_id.
Enviado como current_status (e também status) — é o único campo de fato necessário além do id. Lista baseada em Domain\Shared\Enums\SaleStatus do greenn-back.
Necessário apenas para o histórico da venda não falhar ao salvar; normalmente não precisa mudar.
Usado apenas como rótulo do gateway caso a venda ainda não tenha um definido.
Gerado automaticamente a partir dos campos acima. Você também pode colar aqui um JSON completo (por exemplo, o payload real de um gateway) — os campos acima passam a editar esse JSON no lugar do mínimo padrão, sem afetar os demais campos dele. É esse JSON que será enviado.
JSON inválido — corrija antes de enviar.
